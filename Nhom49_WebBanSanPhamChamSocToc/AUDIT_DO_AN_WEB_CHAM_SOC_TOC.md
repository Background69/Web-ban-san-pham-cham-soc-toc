# AUDIT ĐỒ ÁN WEB BÁN SẢN PHẨM CHĂM SÓC TÓC

## 1. Tổng quan project

* Công nghệ phát hiện được: Jakarta EE 10 Servlet/JSP, JSTL, Gradle War, Tomcat 10, Java toolchain 21, JDBI, MySQL, BCrypt, dotenv, SLF4J SimpleLogger, Gson, Google OAuth, Jakarta Mail, Cloudinary, VNPAY/VietQR.
* Các module chính: authentication/OTP/Google OAuth, catalog sản phẩm, brand/category, cart, checkout, payment bank transfer/VNPAY, order history, review, profile/address/avatar, admin dashboard, admin product/category/brand/order/user/flash sale.
* Cấu trúc thư mục chính: `src/main/java/.../controller`, `src/main/java/.../dao`, `src/main/java/.../services`, `src/main/java/.../model`, `src/main/java/.../util`, `src/main/resources`, `src/main/webapp`, `src/test`, `test`, `compose.yml`, `build.gradle`.
* Nhận xét ngắn về mức độ hoàn thiện: project có khung e-commerce tương đối rộng, nhưng còn rủi ro lớn ở bảo mật, thanh toán, quản trị đơn hàng, cấu hình secret/deploy và tính nhất quán schema. Các issue ưu tiên cao nên xử lý trước khi demo trên domain hoặc môi trường Docker/Tomcat public.

## 5. Issue ưu tiên cao cần sửa trước

* `26` - Secret trong source: cần rotate credential và chuyển sang env/secret manager trước khi public repo hoặc deploy domain.
* `27` và `28` - CSRF chưa enforce và admin mutation dùng GET: có thể làm thay đổi dữ liệu khi admin bị dụ click/link.
* `29` - XSS trong JSP: cần escape output cho dữ liệu review, địa chỉ, order, brand/category, param message.
* `30` - Upload ảnh thiếu giới hạn kích thước và kiểm tra nội dung file.
* `31`, `32`, `33`, `34` - Nhóm lỗi thanh toán/checkout: mock confirm, VNPAY đối soát thiếu, transaction không nhất quán và tồn kho bị giữ.
* `35`, `36`, `37` - Quản lý trạng thái/xóa/hủy đơn hàng ảnh hưởng dữ liệu đơn và tồn kho.
* `38` - Profile fullName không lưu đúng, dễ gây lỗi chức năng tài khoản người dùng.
* `42`, `44`, `45` - Tạo/sửa sản phẩm không transaction, schema enum lệch code, cấu hình DB Docker lệch local.
* `46`, `47`, `48` - Session/redirect, quản trị user và trusted forwarded headers cần xử lý trước khi deploy qua reverse proxy.

## 6. Ghi chú cho người làm Excel

* Nên đưa toàn bộ 49 issue vào Excel vì mỗi dòng có phạm vi và hướng xử lý riêng.
* Có thể gộp khi cần rút gọn: `27` + `28` thành nhóm CSRF/admin mutation; `31` + `32` + `33` + `34` thành nhóm thanh toán/checkout; `22` + `23` + `24` + `45` thành nhóm deploy Docker/domain; `39` + `40` + `41` + `42` + `43` thành nhóm admin product.
* Các issue cần kiểm tra thủ công thêm: `29` cần thử payload XSS trên các trang có dữ liệu động; `34` cần mô phỏng user không quay lại VNPAY return; `48` phụ thuộc cấu hình reverse proxy thực tế; `49` là rủi ro tầng DAO nếu module khác gọi lại service/DAO.
* False positive có khả năng thấp với `26`, `27`, `28`, `30`, `31`, `35`, `38`, `39`, `44`, `45` vì có bằng chứng trực tiếp trong source. `48` có thể giảm mức độ nếu production luôn dùng `VNPAY_RETURN_BASE_URL` cố định và proxy sanitize header. `49` có thể giảm mức độ nếu mọi luồng update/delete địa chỉ đều luôn kiểm tra ownership ở controller.
* Không thấy dấu hiệu SQL Injection trực tiếp trong các DAO đã kiểm tra vì phần lớn dùng JDBI bind parameter; vì vậy không tạo issue SQL Injection riêng.
